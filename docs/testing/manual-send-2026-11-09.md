# 手动发送反馈验证（2026-11-09）

## 交互规则

按用户要求保持发送流程简单：发送失败即提示失败，保留文字和附件，由用户决定是否再次发送。网络恢复、切回页面、SSE 重连和列表刷新只同步已有消息，不自动补发。草稿和手动发送 ID 只保留在当前运行会话中。

## 变更

- Web 移除离线队列服务、自动补发监听及待发送计数。旧 localStorage 键 `syncbox.pending-text.v1` 不再读取或写入；本轮未删除其旧内容。
- Web 失败提示放在对应会话输入区，可以关闭；取消上传使用中性提示并保留附件。
- 人工再次发送相同草稿时复用 clientId，内容或附件变化后使用新 ID，避免响应丢失造成重复保存。此机制不会触发自动发送。
- 文字发送设为 30 秒超时。后端明确确认成功即清除已提交草稿，Web 立即展示返回的消息；后续读取失败与发送失败分开提示。
- 修复 Web 发送中切换会话导致新会话请求被废弃的问题，以及 SSE 刷新失败时未捕获的异步错误。
- Web/Flutter 的列表操作命名为“刷新”。Apple/Flutter 在发送成功后读取失败时提示“消息已发送，列表刷新失败，请刷新查看。”。

## 验证

- Web 单元测试 7 项通过，覆盖设备 ID 和手动发送 ID。
- Web TypeScript 检查及生产构建通过。
- 隔离 Chrome 浏览器回归通过：390px 手机和 1280px 桌面布局无横向溢出，失败保留输入，网络/可见性事件及轮询不补发，手动重试复用 ID，成功后刷新失败不恢复草稿，刷新不发送消息。
- 浏览器回归同时覆盖发送中切换会话、附件失败后手动重试、取消上传保留附件；未产生未处理的页面异常。
- Flutter 32 项测试通过；静态分析无错误、无警告，保留 12 条原有 info 风格提示。
- Apple 21 项测试通过，1 项需要独立后端的集成测试跳过；最后追加的错误上下文透传改动另通过 7 项可靠性测试。
- macOS 完整 Debug 构建通过；iOS Simulator 完整 Debug 构建通过，关闭签名。

浏览器用测试接口拦截全部 `/api/v1/**` 请求，使用独立 context，不读写个人账号或消息。测试入口为 `frontend/web/tests/manual-send.browser.mjs`；依赖本地 Vite 和可用 Chrome，`PLAYWRIGHT_MODULE` 可指定临时安装的 playwright-core。测试未向项目增加依赖。

本轮未重打 APK、IPA 或 Windows 安装包，未进行真机测试；原生修改需要重新构建安装后生效。

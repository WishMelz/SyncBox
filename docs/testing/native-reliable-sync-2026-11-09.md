# 原生同步可靠性验证

## 本轮变更

- Apple 的事件方法加入协议要求，避免经 `APITransport` 调用时落入默认空实现。
- SSE 支持分片 UTF-8、多行 data、CRLF 和心跳；使用独立连接，后台/退出时取消，401 停止重试并进入登录。
- 通知合并刷新，重连后补拉当前内容；Flutter 在请求进行中收到的失效通知会保留到请求结束。
- 文字、图片、附件发送包含 clientId；同一草稿失败重试复用 ID，修改内容或成功后再次发送使用新 ID。
- 后端 multipart 限制允许新增 clientId 字段与五附件组合，原文件数量和大小限制保持不变。
- 当前会话刷新时同步已读；搜索和旧分页不会将整段会话清空未读。未读状态仍为账号共享状态。
- 原生置顶请求改为后端要求的 `pinned` 字段。
- 状态栏区分实时与定时同步。

## 验证结果

- 后端：19 项测试通过，包含真实 HTTP SSE、并发重复文字发送、图片重试、五附件重试及未读接口。测试使用内存数据库。
- Flutter：30 项测试通过，包含窄屏/宽屏组件、连接取消、后台恢复、断线重连、401、刷新期间通知及三类发送重试。
- Apple：19 项核心测试通过；1 项需显式配置独立后端的 API 集成测试跳过。新增 URLProtocol 事件流验证实际协议派发、分片中文解码及取消底层连接。
- macOS 和 iOS（generic device、关闭签名）完整 Debug 构建成功。

Flutter 网络生命周期测试使用真实异步计时；Widget 的虚拟时钟不能完整代表流结束事件的调度。手机/桌面布局仍由 Widget 测试覆盖。

## 范围

未修改个人数据库；未重新打包 APK、IPA 或 Windows 安装包；未在 Android/Windows 真机运行。发送重试状态只保留在运行中的应用内。后续按用户要求确定为失败提示、保留草稿和手动发送，不再计划持久离线队列或自动补发；本轮收尾记录见 [手动发送反馈验证](manual-send-2026-11-09.md)。
